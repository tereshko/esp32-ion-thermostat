`firmware-re/stageO/out/`, пулы, сырые байты `firmware-re/stageB/flat.bin`, база 0x18040000),

## Пункт 1 — ошибка e по режимам — CONFIRMED

Листинг `FUN_180c5dd0` (list_helpers.txt), режим — байт по 0xFFF8CD7D (CD7D, пул 180c6010).
Аргументы вызова в FUN_180c62fc идут в fr4/fr5/fr6 в порядке (CB60[i], CADC[i], CABC[i])
(пулы 62fc: 658c→CB60, 6588→CADC, 6584→CABC):

- mode == 1: `fmov fr5,fr0; fsub fr4,fr0` → e = CADC[i] − CB60[i]
- mode == 2: `fmov fr4,fr0; fsub fr6,fr0` → e = CB60[i] − CABC[i]
- иначе: fr0 = 0.0 (константа по 0x180C6014)

Декомпил 5dd0 пуст по арифметике (Ghidra роняет FPU-аргументы) — решает именно листинг.

## Пункт 2 — коррекция h и гейт — CONFIRMED

- `FUN_180c5e00(C8EC[i], C880[i])`, листинг: `fcmp/gt fr4,fr5` (T ⇔ fr5 > fr4) → при
  C880 > C8EC возврат 0.0; иначе возврат fr5 − fr4 = C880 − C8EC. Итого
  min(0, C880[i] − C8EC_prev[i]); C8EC на этот момент ещё хранит значение прошлого цикла
  (перезаписывается позже в той же итерации).
- `FUN_180c5e16(CD8C, CD1C[i], C8CC[i], gate)`, листинг: при gate == 0 → 0.0; при
  *0xFFF8CBDC (CBDC, пул 180c6018) == 0 → 0.0; иначе fr4·fr5 − fr6 =
  CD8C·CD1C[i] − C8CC_prev[i].
- Гейт считается в 62fc как `fVar8 <= fVar9`, где fVar8 = *C870 и fVar9 = *0xFFF8C90C,
  оба прочитаны на входе, до обнуления C90C. gate = (C870 ≤ C90C_entry) — как заявлено.
- h = h1 + h2 пишется в scratch 0xFFF874E8 и оттуда подаётся в 5e3c как param_2.

## Пункт 3 — нормировка d, q, s — CONFIRMED

В 62fc (декомпил + пулы): fVar7 = (0.0 ≤ e) ? 1.0 (пул 65b0 = 3F800000) : *0xFFF8C9F4
(пул 65ac). Разбиение совпадает с заявленным (e<0 → *K9F4; e=0 → 1.0).
q = fVar11 = CA24[i] / d (пул 65b4→CA04-не-путать: 65b4→0xFFF8CA24 = CA24).
s: `*0x3C12A860 = (CA24[i] * 0.9) / d`, множитель — литерал пула 0x3F666666 = 0.89999997f
(проверен и в flat.bin по 0x180C65B8). s — скалярная ячейка словаря, в 5e3c уходит значением (fr7).

## Пункт 4 — выбор пути, защёлка, полоса, фактор ×15 — CONFIRMED

- Селектор: `FUN_180c6246` дословно зовёт геттер field store с офсетом **0x1FDF**
  (декомпил 6246: `(*(code *)PTR)(0x1fdf, local_8, 1, 1)`). В 62fc: возврат 0 → путь A
  (FUN_180c5e3c), неноль → путь B (FUN_180c5ebc); тот же селектор выбирает фактор C910.
- Путь A, листинг 5e3c: байт C950[i] (пул 601c→0xFFF8C950) ≠ 0 → байт очищается,
  fr0 = fmov.s @(i*4, r5), где r5 = слово по **0x180C6020 = 0xFFF8C958** (прочитано мной
  из flat.bin; в pools-файле 5e3c этого слота не было) → P := C958[i], и ветка прыгает
  сразу на возврат (0x180c5eb8), **минуя кламп** — «unclamped» верно.
  Без защёлки: fr8 = P + G·(CA04[i]/q)·e (fmac, G = *0x3C12A85C, пул 602c),
  затем fr8 += G·(1.0/s)·h (литерал 1.0 пул 6030; fdiv fr7; fmul fr5=h; fmac) —
  т.е. P := P + G·(CA04[i]·e/q) + G·(h/s), как заявлено.
- Путь B, листинг 5ebc: |e| переводится в double (fcnvsd + fabs). Первая проверка —
  double по 0x180C6038; вторая — double по 0x180C6044; пропуск инкремента при
  |e| > hi или |e| < lo. Инкремент только G·(CA04[i]·e/q) (члена h нет).
  Границы включительны с обеих сторон (строгие > и < на пропуске).
- Фактор зоны: в 62fc при селекторе 0 — C910 = CA04[i]·e; иначе C910 = CA04[i]·15.0·e
  (пул 65d4 = 0x41700000 = 15.0). ×15 на пути B, ×1 на пути A — верно.

## Пункт 5 — кламп P двусторонний [0, C870] — CONFIRMED

Хвост клампа в листингах 5e3c и 5ebc идентичен дословно: результат < 0.0 → вернуть 0.0;
результат > *0xFFF8C870 (C870, пул 6034) → вернуть *C870; иначе вернуть результат.
Плюс исполнительное доказательство — вектор V10 (см. п. 10): сырой P = −210.67 → 0.

## Пункт 6 — сборка C8EC/C8CC/CD44, multi, skip, freeze — CONFIRMED (с уточнением)

- C8EC[i] = C910[i] + P[i] (62fc, пулы 67c8→C910, 67cc→0x3C12A864, 67d0→C8EC);
  побочно C930[i] := P[i].
- multi: bVar1 = (1 < FUN_180c5d90()) && (*CBDC != 0). Счётчик 5d90 перебирает 8 зон через
  FUN_181f035c → FUN_181f0344(CBA9[i]) = (b != 0 && b != 5) — n = #{i: CBA9[i] ∉ {0,5}} верно.
- C8CC: multi → кламп [0, C880[i]] (начальное 0.0, затем min с C880); иначе max(C8EC, 0).
  Аккумулятор C90C обнуляется на входе, суммирует только C8CC вычисленных зон;
  в конце *CD44 (пул 67f0→0xFFF8CD44) = *C90C. CD44 = Σ C8CC верно.
- Skip: предикат зоны FUN_181f0428 → FUN_181f0408(i, CBA9[i], CBA0[i]) =
  (CBA0[i] == 1 && CBA9[i] != 5 && CBA9[i] != 0) (пулы 04e4→CBA0, 04e8→CBA9).
  В 62fc: предикат == 0 ИЛИ *CD7D == 3 → FUN_180c5f5c().
- Freeze: обновление P обёрнуто в `if (*0xFFF8CD73 == 0)` (пул 65c0→CD73);
  при CD73 ≠ 0 P не трогается (вектор V8). Уточнение: C910/C8EC/C8CC при этом
  пересчитываются как обычно — «freeze» относится только к рекурсии P, как и заявлено.
- **Уточнение точности:** FUN_180c5f5c обнуляет C8EC[i], C910[i], scratch h и P[i]
  (и ставит C930[i] := P[i] = 0), но **не пишет C8CC[i]**. Функционально разницы нет:
  прибавление C8CC в аккумулятор стоит внутри вычислительной ветки, skipped-зона в сумму
  не попадает. Проза «zeroed by FUN_180c5f5c» в части C8CC неточна, на CD44 не влияет.

## Пункт 7 — FUN_180c5fc6: double 0.05, CE00 не питает CD44 — CONFIRMED (с уточнением)

- Сырые байты flat.bin по 0x180C6060: слова **3FA99999 A0000000** — в точности как заявлено;
  как BE double это 0.05000000074505806 ≈ 0.05. Чтение тем же словом как float даёт 1.325 —
  та самая ловушка старшего слова.
- Листинг 5fc6: FPSCR PR-бит выставляется, fr5 (= e) → fcnvsd → fabs (dr8 = |e| double);
  fmov.s-пара грузит double 0x180C6060; fmul в double-режиме; fcnvds обратно во float;
  затем FPSCR восстановлен и fmac с float по 0x180C6068 = 0x3F733333 = 0.95f по fr4 (= CE00[i]).
  Итого CE00 := 0.95·CE00 + 0.05·|e| — верно (0.95 — float-константа, 0.05 — double,
  произведение считается в double и урезается во float).
- «Не питает CD44»: по всему корпусу stageO только FUN_180c62fc и FUN_180c4322 ссылаются
  на 0xFFF8CD44. **Уточнение:** CE00 не мёртв — FUN_180c6070 читает CE00[i] как гейт
  (CE00[i] < 0.13, литерал пула 0x3E051EB8) для обновления массивов CE20/CE40; но ни CE00,
  ни CE20/CE40 входами суммы в 62fc не являются. На формулу CD44 влияния нет.

## Пункт 8 — писатель 2 FUN_180c4322 — CONFIRMED (с уточнением)

- Декомпил 4322, первая же операция: `*DAT_180c4404 = param_1`, пул 4404 → **0xFFF8CD44**.
  CD44 := param дословно; остальное — арбитражная бухгалтерия (CA75/CA76, 0.5, 0.1).
- Селектор FUN_180c4224, пулы: 43ec = 0.1f (0x3DCCCCCD), 43f4 = 1.0f, 43f8 → 0xFFF8CD4A (CD4A).
  Ветка 2 достижима только из `else if (param_1 <= 1.0)` при уже проваленном
  `param_1 <= 0.1`, и внутри неё CD4A ∈ {1,2,3} даёт ветку 3, иначе ветку 2.
  Диапазон — (0.1, 1.0]: нижняя граница исключена (arg ≤ 0.1 уходит раньше),
  верхняя включена (arg ≤ 1.0 проходит). Как заявлено.
- **Уточнение:** у селектора есть ещё два предусловия состояния, в утверждении не названные:
  ¬(*0xFFF874CC < *0xFFF874D0) (первая ветка форсит селектор 1) и байт словаря
  по 0x3C12A852 ≠ 0 (иначе селектор 0). Условия «диапазон + CD4A» необходимы и —
  при этих двух предусловиях — достаточны.

## Пункт 9 — FUN_1809f4a4: в холоде C870 = CCC4[CC5A−1] — CONFIRMED

## Сверка констант из flat.bin (собственные чтения)

| Адрес | Слова | Значение | Где используется |
|---|---|---|---|
| 0x180C6020 | FFF8C958 | база C958 | защёлка пути A (слот пула, отсутствовал в pools-файле) |
| 0x180C6038 | 40000000 00000000 | double 2.0 | верх полосы пути B |
| 0x180C6044 | 3EE4F8B5 80000000 | double 9.9999997e-06 ≈ 1e-5 | низ полосы пути B |
| 0x180C6060 | 3FA99999 A0000000 | double 0.05000000074505806 ≈ 0.05 | коэффициент CE00 |
| 0x180C6068 | 3F733333 | float 0.95 | коэффициент CE00 |
| 0x180C65B8 | 3F666666 | float 0.9 | множитель s в 62fc |

Замечание по константам полосы и CE00: хранимые double — не ближайшие к 1e-5/0.05
представления IEEE (младшие слова 80000000/A0000000 вместо 88E368F1/9999999A) —
это усечённые значения, расхождение ~2.5e-7 относительных; на формулу в заявленном
виде («1e-5», «0.05») не влияет.
